# Assamese Temporal Corpus — TIMEX3 Annotation Guide

## Files

| File | Contents |
|---|---|
| `assamese_temporal_corpus_A.txt` | Set A, 50 docs, plain text |
| `assamese_temporal_corpus_A_TIMEX3.txt` | Set A, 50 docs, TIMEX3-annotated |
| `assamese_temporal_corpus_C.txt` | Set C, 50 docs, plain text |
| `assamese_temporal_corpus_C_TIMEX3.txt` | Set C, 50 docs, TIMEX3-annotated |

The plain files are generated by stripping TIMEX3 tags from the annotated files,
so the two versions are character-for-character identical outside the tags.

- **Set A** — general synthetic Assamese news (floods, accidents, raids, school
  events, health camps, weather, wildlife, exams, sports, markets, agriculture…).
- **Set C** — synthetic news modelled on real topic patterns observed in Assamese
  outlets (student-body protests, NEET results, centenary events, drug raids,
  missing migrant workers, elephant road crossings, highway repair deadlines,
  land scams, cricket league finals, Janmashtami, GLOF risk, layoffs, voter-list
  revision…). All names, numbers and incidents are invented.

## Document format

```xml
<document>
<DCT tid="t0" type="DATE" value="2026-07-02T13:20:00+05:30"
     temporalFunction="false" functionInDocument="CREATION_TIME">2026-07-02T13:20:00+05:30</DCT>
<text>
… Assamese news text with inline <TIMEX3> tags …
</text>
</document>
```

## Attribute conventions

**tid** — `t0` is reserved for the DCT; in-text expressions are numbered `t1…tn`
in document order.

**type** — `DATE`, `TIME`, `DURATION`, `SET`.

**value** — ISO-8601 / TimeML normalisation:
- Full date: `2026-07-02`; month: `2026-07`; year: `2026`
- ISO week (for "আহি থকা সপ্তাহত"): `2026-W28`
- Clock time: `2026-07-02T10:00`
- Part of day: `TMO` (পুৱা), `TAF` (বিয়লি), `TEV` (সন্ধিয়া), `TNI` (নিশা/ৰাতি) —
  e.g. `2026-07-02TMO`
- Duration: `P4D`, `P1W`, `P3M`, `P1Y`, `PT2H`; underspecified counts use `X`
  (`PXD`, `PXM`, `PXY`, `PXW`) for vague quantifiers like "কেইদিনমান", "কেইমাহমান"
- Vague deictics: `PRESENT_REF` (বৰ্তমানলৈকে, এতিয়াও), `PAST_REF` (যোৱা নিৰ্বাচনত,
  যোৱা বৰষুণৰ বতৰত), `FUTURE_REF` (আহি থকা বৰষুণৰ বতৰত, আহি থকা মাহবোৰত)
- Recurring dates: `XXXX-WXX-6` (প্ৰতি শনিবাৰে), `XXXX-WXX-7` (প্ৰতি দেওবাৰে)

**temporalFunction / anchorTimeID** — `temporalFunction="true"` with
`anchorTimeID="t0"` whenever the value had to be computed from the DCT. This
includes bare day–month expressions such as "৪ আগষ্ট", since the year is
recoverable only from context. Fully explicit values (e.g. "২০২৩ চনৰ") and
DURATION values carry `temporalFunction="false"`.

**mod** — `APPROX` (প্ৰায়), `ON_OR_BEFORE` (…ৰ ভিতৰত, …লৈকে). Others in the
TimeML inventory (`BEFORE`, `AFTER`, `START`, `MID`, `END`, `LESS_THAN`,
`MORE_THAN`, `EQUAL_OR_LESS`, `EQUAL_OR_MORE`) are permitted but unused here.

**beginPoint / endPoint** — durations bounded by the DCT are anchored to it:
past-facing durations ("বিগত ৪ দিনে", "যোৱা এমাহ") take `endPoint="t0"`;
future-facing durations ("আহি থকা তিনি মাহৰ", "আহিলে ৭ দিনৰ") take
`beginPoint="t0"`. Unbounded durations ("তিনিমাহজুৰি", "প্ৰায় এঘণ্টা") carry
neither.

**quant / freq** — used on `SET` only, e.g.
`<TIMEX3 type="SET" value="P1D" freq="P1D">প্ৰতিদিনে</TIMEX3>`.

**functionInDocument** — `CREATION_TIME` on the DCT; omitted (i.e. `NONE`) on
in-text expressions.

## Temporal phenomena covered

- Absolute dates with and without weekday ("২০ আগষ্ট", "৪ আগষ্ট তাৰিখে")
- Deictic dates: আজি, আজিৰ পৰা, আজিলৈকে, বৰ্তমানলৈকে
- Relative past: যোৱা সোমবাৰ, গতবছৰ, যোৱা মাহৰে, যোৱা নিৰ্বাচনত
- Relative future: আহি থকা সপ্তাহত, আহিলে বছৰত, আহি থকা ১৫ ছেপ্টেম্বৰ
- Clock times and part-of-day: পুৱা ১০ বজাৰ, বিয়লি প্ৰায় ৫ বজাত, গভীৰ ৰাতিলৈকে
- Durations, bounded and unbounded: বিগত ৪ দিনে, প্ৰায় ২ ঘণ্টা, দীৰ্ঘ ১৪ বছৰৰ,
  যোৱা তিনি দশক
- Vague/underspecified quantities: কেইদিনমান, কেইমাহমান, কেইবছৰমান
- Recurring sets: বাৰ্ষিক, প্ৰতিদিনে, প্ৰতি শনিবাৰে, প্ৰতি দেওবাৰে

## Validation performed

Both annotated files were machine-checked for: XML well-formedness of every
document; unique, gap-free, document-ordered `tid`s with `t0` on the DCT;
`anchorTimeID` present whenever `temporalFunction="true"`; well-formed ISO
duration values; and — most importantly — agreement between the *surface string*
and the *normalised value* for 95 day–month expressions, 10 weekday names,
47 clock times, 45 part-of-day tokens, 37 year values and 20 ISO week values.
All 254 checks pass with zero mismatches.

## Known annotation decisions you may wish to revisit

1. Bare day–month dates are marked `temporalFunction="true"`. Some TimeBank-style
   guidelines treat these as `false`. Flip if your scheme differs.
2. "নিশা ১২ বজাত" (midnight) is normalised to `T00:00` **of the following day**.
3. Vague durations use the `PX…` underspecification convention; some schemes
   prefer omitting `value` entirely.
4. Event tags (`<EVENT>`) and temporal links (`<TLINK>`) are **not** included —
   this is TIMEX3-only annotation.
